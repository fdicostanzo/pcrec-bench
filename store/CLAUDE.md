# store/ — the record store (OD-B6)

```
store/
  machines.tsv                       the machine registry
  index.tsv                          regenerated by `pcrecbench index`
  records/<subbench>@<version>/<testee_id>/<record_id>.jsonl
```

Records are DATA and are committed (requirements §6; OD-B6 revisits when size
demands). They are written once and never edited — a re-measurement is a new
record, and the `-<n>` suffix on a name that already exists is what stops a
same-second re-run from silently clobbering a baseline.

**The file name IS the record id.** `validate.py --check-filename` (rule X4)
enforces it, so a record can be identified from its path alone.

**`machines.tsv` is hand-maintained by the harness, not by hand.** A box that
is not in it makes a run REFUSE rather than invent an id: `--machine-id SLUG`
registers one, once, deliberately (record_schema.md §6.5). An id is never
reused for a different box and a box never gets a second id — either mistake
splits or merges a machine's history silently, which no later analysis can
undo.

Nothing under `records/` may be a smoke. Records written by `make check` go
to a scratch store under `build/` and carry `synthetic: true`.
