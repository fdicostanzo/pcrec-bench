# store/ — the record store (OD-B6)

```
store/
  .canonical                         THE MARKER: this tree is the canonical store
  machines.tsv                       the machine registry
  index.tsv                          regenerated by `pcrecbench index`
  records/<subbench>@<version>/<testee_id>/<record_id>.jsonl
```

Records are DATA and are committed (requirements §6; OD-B6 revisits when size
demands). They are written once and never edited — a re-measurement is a new
record, and the `-<n>` suffix on a name that already exists is what stops a
same-second re-run from silently clobbering a baseline.

**The file name IS the record id.** `validate.py --check-filename` (rule X4)
enforces it, so a record can be identified from its path alone.

**`machines.tsv` is hand-maintained by the harness, not by hand.** A box that
is not in it makes a run REFUSE rather than invent an id: `--machine-id SLUG`
registers one, once, deliberately (record_schema.md §6.5). An id is never
reused for a different box and a box never gets a second id — either mistake
splits or merges a machine's history silently, which no later analysis can
undo.

Nothing under `records/` may be a smoke. Records written by `make check` go
to a scratch store under `build/` and carry `synthetic: true`.

## Two tiers, two kinds of store (schema v1.2, [B10]; Frank's I-4)

**This tree is the CANONICAL store, and `.canonical` is what says so.**
Only `tier: pinned` records live here — a committed engine revision
built by `pin.sh`, measured under the quiet gate and the window
handshake. A **`tier: scratch`** record (a provided binary via
`pcrec-local`, or any `pcrecbench quick` cell) goes to a SCRATCH store:
`$PCRECBENCH_SCRATCH_STORE`, or `build/scratch-store/` (gitignored). A
scratch store has the same layout, its own `index.tsv`, and borrows this
registry's machine ids (one box, one id).

The rule is the STORE's, not the harness's, and it is enforced twice:
`store.write()` REFUSES a scratch record into any root carrying the
marker (the harness asks the same question first, before it gates or
measures anything, so a refused run touches nothing), and
`store.index()` of a marked root REFUSES to list a scratch record that
got there some other way — the index is what the reporter and the
rankings read, and it must not launder one. `make check-harness`
proves both by sabotage (a scratch record planted by hand). The marker
is a file rather than a path comparison so the rule holds from a
worktree, whose `store/` is a checkout of this same tree.

`.canonical` is committed. Do not create one in a scratch store; do not
delete this one.
