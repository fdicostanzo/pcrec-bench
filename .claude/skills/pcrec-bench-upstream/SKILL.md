# /pcrec-bench-upstream

The spec is `docs/design/upstream_pipeline_v1.md`; this is the procedure.
Surfaces: `docs/dev/upstream/findings.tsv` (the registry), the narrative
`docs/dev/upstream_findings.md` (one `## U<n>` per id), `docs/dev/upstream/
repro/U<n>/`, `docs/dev/upstream/notes/<engine>-<date>.md`, and the one
interface `python3 tools/upstream.py {check,list,repro,new,status}`.
`make check-upstream` must stay green after every change.

## Hard rules

- **pcrec is out of scope.** pcrec findings go to `docs/dev/outbox_to_pcrec.md`.
- **Nothing leaves the repo without Frank's per-note APPROVED.** Sending is
  public and in his name. Tracker/changelog SEARCHES are read-only and fine;
  never open an issue, comment, PR or post. When a note is approved, Frank
  sends it or explicitly tells you to, naming the channel.
- **Check the engine's documented semantics BEFORE calling anything a bug**:
  the engine's own syntax doc, and for POSIX engines (TRE) the POSIX spec
  and glibc's regcomp as a control. A note that tells a maintainer their
  standard-conforming behaviour is wrong is worse than no note. (2026-09-27:
  TRE's literal `\` in `[...]` is POSIX, and it was nearly sent.)
- **A "bug" that is really our adapter feeding a dialect the engine does
  not speak is a BENCH finding**: file it in plan.md / the testee's
  CLAUDE.md, not upstream.
- A repro is STANDALONE: the engine's own tool (`pcre2test`) or a tiny
  program linking only the engine. It never reads the store. Big subjects
  are generated by `run.sh` into `$UPSTREAM_SCRATCH`, never committed.
- Performance repros run single-core (`taskset`), last seconds, take the
  median of ≥5 runs, state their PRESENT threshold, and record the box load.
  Only run them on a quiet box (BD3).

## Procedures

**File** (a lane or ledger found something): `tools/upstream.py new
--engine E --kind correctness|performance|compatibility|semantics
--summary "…"`. Then fill the narrative section: the record id(s) and
row(s), the numbers, and the reading, marked unverified. Status
OBSERVED.

**Reproduce**: write `repro/U<n>/{README.md, run.sh, the repro,
expected.txt}` per design §2.2. `run.sh` exits 0 PRESENT / 1 ABSENT /
2 CANNOT-RUN and ends with `U<n> PRESENT|ABSENT|CANNOT-RUN <engine>
<version> <evidence>`. Run `tools/upstream.py repro U<n>`, then `status
U<n> REPRODUCED`. When an ablation or a source reading confirms the
cause, move to `UNDERSTOOD` (this may come before REPRODUCED).

**Triage for sending**, one finding at a time:
1. Check documented semantics (rules above). If it is intended, move to
   `NOT-A-BUG` and cite the doc.
2. Find the latest upstream release. Build it in `$UPSTREAM_SCRATCH` if
   the build is modest; otherwise source-diff the relevant file. Run
   `repro --engine-build PATH --record`. If the finding is ABSENT on the
   latest release before we sent anything, it is `STALE`, or `FIXED`
   with the changelog citation.
3. Search the tracker and the changelog. If an issue already covers it:
   `status … KNOWN-UPSTREAM --tracker URL`. Otherwise record
   `searched:<date>:none-found` in `tracker`.

**Draft**: write one `notes/<engine>-<YYYY-MM-DD>.md` per upstream per
batch, per design §4. It is written for the maintainer: no bench jargon,
self-contained cases, numbers with box and method. The header block
lists the ids, the channel, and a blank approval line. Then `status …
DRAFTED --note PATH`.

**Approve / send**: only on Frank's word. Record the date in the
narrative and set `status … APPROVED`. After sending, set `status …
REPORTED --tracker URL`.

**Re-verify** (at a new engine release, or monthly): `tools/upstream.py
repro --all` against the pinned and latest builds. A REPORTED finding
that is now ABSENT becomes `FIXED`. Record the answer in the narrative.

**Hand-off**: read lanes that meet another engine's behaviour list it in
their ledger's candidates. The manager (or a lane briefed with this
skill) runs **File**.

## Session checklist

`tools/upstream.py list` shows the state. Look for anything OBSERVED
without a repro, anything DRAFTED awaiting Frank, and any REPORTED
finding whose tracker has moved. Finish with `make check-upstream` and
commit.
