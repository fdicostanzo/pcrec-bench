# null_band_v1 — the null-control band and the D119 bar in cross-pin reports

STATUS: IMPLEMENTED (2026-09-25, lane `b79nullband`, plan row [B79];
reporter **v22**, catalogue **3.7**). The design of record for how the
reporter states D119's landing bar. Before this note, no design note
specified the bar: it lived in each ledger's own prose ("a TARGET cell
must improve by more than its IQR; every other cell must not regress by
more than its IQR", I-87(a)/I-95), computed by hand from the records in
a read-only lane.

Sources: inbox I-93 block B (the ask, filed as [B79]), I-104 (the banded
spec, the authority), I-99/I-100/I-101 (the class-pure views and the
standing cross-class query the bar is restated in), pcrec's
`docs/dev/optloop/cycle2_batch2_reading.md` §1 (the worked reading that
motivated the bands; read at pcrec commit 4fe938ad, read-only).

## 1. Why a band

The D119 bar's noise model is a cell's own within-window IQR over five
trials. A cross-pin comparison spans TWO windows, often hours apart. The
IQR cannot see the between-window component. The cells whose artifact
did not change across the pin measure that component directly, at no
extra cost, in every cross-pin report. pcrec's cycle-2 reading found
131 of 192 capability artifact-configs program-identical across
8d716693 → b1885a83, with every one of the 34 non-target regressions the
ledger named sitting on one of them, up to +41.09% at floor scale.

## 2. Identity: our own census, not a record field

**Finding: the records carry no program hash.** A pcrec compile row's
`engine_metadata` has `emit_bytes` / `emit_code_bytes` / `artifact_bytes`
and the mechanism stamps. None of them establishes identity. Every re-pin
adds stamp lines, so EVERY artifact's size moves by a pin-specific
constant (the `B84_STAMP_LINE_*` family), and two different programs can
share a size.

So identity comes from `tools/program_identity.py`. The tool re-emits
every pattern × form at both pins. It uses the SAME pinned binaries the
records' `emit-c` phase ran (`build/pcrec-<pin>/build/pcrec`; the
record's `testee.binary.sha256` is checked against them when present).
Each config runs under its OWN flags, read from the record's
`testee.build_flags` and required equal across the pin. Pattern bytes
come from the sub-bench and are checked against the record's
`patterns[].canonical_sha256`. The tool emits WITHOUT `-fcomments` (off
by default at every pin since 25b1984f; the `.so` is independent of
comments, [B58]). It then compares `.c` + `.h` after dropping ONLY:

1. the `/* Generated by pcrec ... */` line (it names the abi and version);
2. the `.abi = N,` initializer;
3. every `#define` whose NAME is defined on one side only (a new stamp:
   `RX_REQ_RUN` at b1885a83, `RX_REQ_WHY` at 6ef76820, ...).

A stamp present on both sides compares VERBATIM. A moved value
(`RX_REQ_BYTE` 114 → 98) therefore counts as a changed program, and it
always is one, because the stamp names the emitted code's own constant.
Output: `reports/identity/<subbench@version>/<engine>_<old>__<new>.tsv`,
deterministic, re-derivable with `--check`, committed beside the reports.

Cross-check against pcrec's `nullctl.json` for 8d716693 → b1885a83
(their darwin census over three configs, plain form): **192/192 agree**.
The census line in the file records this.

Covariate NOT in the identity: this project's own shim (`shim.c`) is
linked into every `.so` and changes at most re-pins. It moves the
identical and the changed populations alike, so a shim-induced layout
shift lands INSIDE the band ([B22]'s year4 ELF-page lesson). That is
where it belongs.

Proposed fix (OWED as a ruling, not built by this lane): the pcrec
adapter could stamp a `program_sha256` into each compile row's
`engine_metadata`, computed with rule 2's normalization at emit time
(schema v1.6 minor, and a `STAMP_SCOPE`-style field declaration). The
census would then become a cross-check instead of the source, and
future pairs would need no re-emission.

**RULED (BD13) and BUILT ([B88], lane b90repin, 2026-09-25) -- with one
change to the proposal above, forced by the data.** The field cannot use
the three rules above: rule 3 is PAIR-RELATIVE (which `#define`s are
one-sided depends on the other pin), and a compile row is one artifact.
So `tools/program_identity.py` gained normalization **v2**
(`normalize_one`), one artifact at a time: C comments removed and blank
runs collapsed (so `-fcomments` cannot move it -- the adapter emits WITH
it, the census WITHOUT); the shared `PCREC_RX_ABI_H` declaration block
dropped (pcrec emits it identically into every artifact of a pin); the
`rx_info` reflection initializer dropped when nothing reads it (rule 2
is a member of it); the artifact's own `#include` canonicalised; and
every `#define` that NO other emitted line references dropped (subsumes
rule 3: a one-sided stamp is unreferenced; a macro the program reads --
`RX_NCAPS`, `RX_RESUME_FRAMES`, the slot indices -- stays verbatim).
The record field `engine_metadata.program_sha256` (record schema v1.7,
declaration type `sha256`) is `program_sha256_of_files()` of that
module, imported; a v2 census file's sha columns are the same values.
The band reads the FIELD first, the census as the fallback, and names
any disagreement where a cell has both (`pcrecbench/nullband.py`).

The data that forced v2, measured at [B90]: at 6ef76820 → ce658cb7 abi
32 ([VAR]) grew the ABI block and the `rx_info` initializer of EVERY
artifact, so the v1 rules read all 373 compiled capability rows
`changed` -- an EMPTY band. v2 reads 325 identical / 48 changed (the 12
K64 fix-A rows and 36 backreference rows whose `rx_bref_match` became
`rx_span_match`). On the three committed v1 pairs v2 agrees with v1 on
1,144 of 1,152 rows; the 8 others are one pattern whose
`RX_VM_PREFILTER_LANG_WHY` prose ("size cap retry, exact N > cap")
echoed the pin's own new stamp line in its byte count with the program
identical -- v1's "a moved stamp value is always a changed program"
sentence above is FALSE for that one prose stamp, and v2 does not rely
on it. The v1 files stay re-derivable (`--check` reads the version off
the file's first line); v2 is the default for a new pair.

## 3. The band

- **Population:** per cross-pin PAIR (the testees R8's `Δ vs previous
  version` already pairs, `_previous_pin_testee`), every set cell
  measured, pinned, timed and passing on BOTH sides whose census verdict
  is `identical`.
- **Strata:** per (regime, baseline scale). Baseline scale uses the
  BEFORE (older pin) set-grain median: `>=1us` (≥ 1,000 ns), `100ns-1us`,
  `<100ns` (I-104). Every regime the pair's cells span gets all three
  strata printed, empty ones included.
- **Half-width (symmetric):** the largest |Δ%| any null cell of the
  stratum reached. This is pcrec's own "worst null cell" reading, and
  I-104's worked example ("2 of the 17 are outside the band") uses it.
  The range (min, median, max Δ%) is printed beside it, so the
  distribution's asymmetry stays visible.
- **Sufficiency, `N_MIN = 10`.** The half-width is a sample maximum. For
  exchangeable null cells, the chance that one more null cell exceeds
  the maximum of n is 1/(n+1): ≤ 9.1% at n = 10. That is the loosest
  bound this project will call a noise floor. Below it the stratum reads
  `insufficient (n=K < 10)`, or `empty (n=0)`, BY NAME. Its band is never
  used. Every verdict in it reads `... (IQR only: band n=K < 10)`. The
  fallback is stated, never silent.

## 4. The bar

    Δ%   = (after_median − before_median) / before_median × 100
    IQR% = Type-7 IQR of the BEFORE side's per-trial set sums / before_median × 100
    bar  = max(IQR%, band)          (band only if the stratum is usable)
    verdict: regress if Δ% > bar; improve if Δ% < −bar; within otherwise

The IQR is the BEFORE side's, the ledgers' own primary "before-IQR"
reading. For 5 trials it is x3 − x1 of the sorted sums. The per-trial
sums are `reduce.SetCell.sums`, which the reporter has always held at
set grain. A program-identical cell is rendered `null-control`, never
scored against a band it belongs to.

## 5. Surfaces (reporter v22)

- **Scope:** cross-pin reports at SET grain only. A report with no
  cross-pin pair renders nothing new. A pair with no census file renders
  `NO NULL BAND for this pair` naming the expected path, and no D119
  column. At subject grain the section is one sentence saying the band
  is set-grain only.
- **Markdown:** a `## Null-control band` section after the Query
  section (the rule, per-pair census + cell counts, and the strata
  table). A `D119 bar` column beside `Δ vs previous version`:
  `+80.83% vs bar 8.77% (band) → regress`. Every ranking view restates
  the bar with ITS OWN threshold population's counts: each class-pure
  view (I-99) and the mixed or unsplit one.
- **TSV:** a conditional LAST header key `null_band:` (after
  `floor_pattern`, so no key moves), plus these rows:
  - `null_band` rows: one census row, and one `band_pct` row per
    stratum carrying status/min/median/max.
  - one `d119` row per cross-pin cell. `value` is the base token
    (`improve`/`regress`/`within`/`null-control`). `gave_up_summary`
    carries `delta_pct`, `iqr_pct`, `band_pct`, `bar_pct`, `bar_source`
    (`band`/`IQR`/`IQR-only`/`null-control`), `stratum`, `identity`,
    `capture_class`, `previous`, `before_ns` and `after_ns`.
    `delta_verdict` carries R8's own verdict.
  - `d119_view` rows: the per-view counts (`yes`/`no`/`mixed`, or `all`).
- **I-101 query clearance column:**
  `gap% = (nocaps − competitor)/nocaps` against the wider of the two
  cells' IQRs and the nocaps cell's own stratum band. The overall phrase
  is one of `CLEARS max(IQR, band)`, `within max(IQR, band)`,
  `clears IQR only`, `within IQR` or `no verdict`, followed by the
  numbers. On a single-pin report the band is stated absent by name.
  **[B87] (2026-09-25, the manager's ruling on this design's own OWED
  item, `docs/dev/lanes/b79nullband_report.md` 0 finding 5):** the
  QUERY ITSELF (`_cross_class_query_hits`, [B82]/I-101 -- upstream of
  the band/IQR clearance this bullet describes) now pairs a pcrec
  YES-class row against pcrec `auto-nocaps` AT THE SAME PIN ONLY; a
  cross-pin pcrec-caps-vs-pcrec-nocaps pair is a pin delta (this band's
  own territory, not a class anomaly) and no longer produces a hit at
  all. A non-pcrec competitor is unaffected. See `pcrecbench/report.py`'s
  `[B87]` module-docstring section and `docs/dev/lanes/b87query_report.md`.

## 6. Interpreter (catalogue 3.7)

- **R-DELTA-5**, the class-aware D119 verdict. It fires on every `d119`
  row whose verdict is `improve`/`regress` and aggregates by
  (capture_class, regime, direction), so no bullet pools classes. The
  extremal is |Δ%|.
- **R-STATUS-15**, the standing query fires. It fires on every
  `query_yes_beats_nocaps` hit and aggregates by (regime, competitor,
  clearance verdict). The extremal is the competitor's speedup.

Neither computes a threshold. Both copy the reporter's own tokens.
