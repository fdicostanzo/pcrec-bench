## Findings the manager should rule on

1. **The v1.4 trial-agreement rule is blind to every substitution record.** `reduce._ns_per_iter_judged` (and `validate.py`'s second implementation, gate_shape_v14.md 3.5) judge a trial only if `timing.iterations > 1`; the charter fixes `iters = 1` for this regime (3.1.2), so every group is "unjudged: few_timed_trials" and the dry run's block reads `agree 0/0 groups -- nothing judged (8 rows unjudged)`. At the PINNED tier that means a substitution record is `measured` whatever its trial spread (the spread rule `inconclusive-spread`/exit 4 can never fire for it). Not fixed here (it is Frank's rule and X32 has an independent implementation). Options: judge `iterations == 1` rows for the `substitution` regime (an X32/X13 revision under record_schema.md 4's rule-revision clause), or accept it and let the reporter show the 5 raw trials. Ask: owner manager -> Frank, before the first pinned subst window.
2. **`match.subst` is REQUIRED on every substitution row (X36) but "describes the validated output"**; a `gave-up` / `crashed` / `timed-out` / `truncated-subject` row has none. `substrun` writes PLACEHOLDERS (gate `wrong`, nsubst 0, out_bytes 0, out_sha256 = sha256 of the empty string) and says so in the row's `diagnostic`. They are never read as an output (the outcome is not `matched-as-expected`, X37), but a reader of `subst` alone is misled. Schema fix (make `subst` optional for outcomes that produced no output, or add a gate value) belongs to the schema owner.
3. **Trials 2..N rows carry the EXPECTATION'S `out_sha256`** (X43 wants it constant across trials; the hash is taken once, on trial 1, and trials 2..N are checked only by length + count as chartered). Equal to the observed hash by construction on every written row, since a length/count difference raises before anything is written; a trial-2 output with the same length and count but different BYTES would not be seen. The charter accepted that; stated here so nobody assumes more.
4. **The sidecar is still `subst.toml`.** `Subbench` accepts both names (`SIDECAR_NAMES`) so `run` works; the generic gates (`subbench_dirs()`), the reporter's set-id lookup (`report.py` 1889) and the importer (`importer.py` 55) enumerate `subbench.toml` only and so do not see the set. Renaming is the reporter step's integration (plan [B140] step 5) and carries a decision: whether `selfcheck.py`'s generic gates (floor pattern by oracle, 9-column `expectations.tsv`, etc.) should skip a `substitution`-only set. OWED: owner manager, trigger step 5.
5. `quick` does not know the substitution regime (`QUICK_REGIMES`); `report`/`viewer`/`frontpage`/`trend` were not exercised on a substitution record (none is in `store/`). OWED to step 5.
6. JIT-stack probe (8a item 11): no `-46` on acc-small for any of the 8 cases under `pcre2-jit` (case 7's lookahead + backreference included). acc-main is the first window's check.
7. `run_cell` now resolves the adapter before the missing-subject-files check (so a `subst_only` testee on a set whose subjects are not generated is refused by name rather than by "subjects missing"); `missing_subject_files` gained `limit=` (a `--subjects K` cell needs only the first k files). Both are order/strictness changes confined to error paths of other sets.
