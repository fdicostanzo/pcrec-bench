## Predictions, stated before the build (boilerplate discipline)

From I-77 (1)'s own text, before compiling anything:

1. `list_axes.tsv` gains exactly two rows: a `comments` axis, order 1
   `essential-only` (the default) and order 2 `full` (`-fcomments`).
2. `struct rx_info` unchanged — [EMIT-VERB] is a comment-emission
   default, not a new observability field — so the shim floor stays 16.
3. Held artifact SOURCE size (raw `.c`+`.h` bytes) moves down ~a third
   (pcrec's own −36.3% corpus figure); OBJECT bytes, answers, refusal
   sets, and every stamp value do NOT move.
4. `list_definitions.tsv` and `list_limits.tsv` were not expected to
   move (nothing in I-77 (1)'s text names a new definition or numeric
   limit).

**Scored below**: (1) and (2) confirmed exactly. (3) was RIGHT in
direction but WRONG in an important particular — see "Size books" below:
this project's own `emit_bytes`/`emit_code_bytes` measure was *already*
comment-excluded, so the −36% never reaches it; only the truly raw file
size moves, and nothing this project tracks as a number is built from
that raw size. (4) was WRONG: `list_limits.tsv` gained one row, from
[REVW.4] (a different, co-landing pcrec change), fully traced and
explained below — not silently absorbed.
