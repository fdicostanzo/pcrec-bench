A pattern whose `requires=` tags a config does not declare is never

pattern a config declares it supports but the engine refuses is a
`did-not-compile` row (R1's population, §5). `prp-ingreek` (`\p{InGreek}`)
is refused by the ORACLE itself and has no expectation rows, hence no

### 0.3 Grain caveats that bound every verdict below

- **vectorscan-block-nosom-utf8 is BOOLEAN grain**: it answers matched /
  not matched, never a span or a count. A wrong SPAN (`prp-latin` on rust/
  re2/onig) or a wrong COUNT (`prp-han` throughput) is invisible to it by
  construction. Every clause reading `n_wrong` over it (P4.b, P6, P10.a) is
  structurally blind to those two failure kinds. Its throughput cells stop at
  the first match and are NOT comparable to find-all cells (§2.3 excludes it).
- **pcre2-utf-dfa** is longest-at-leftmost; its one wrong cell
  (`qnt-lazy-2b` = `é+?`, observed [0,8)/[0,6) against the oracle's [0,2))
  is that documented convention and the reason P5.b left it out.
- **whole-subject forms**: the set declares no `match` regime, so no
  whole-subject artifact is ever MEASURED. They are still compiled and
  reported in the compile section (pcrec, onig, rust, vectorscan) — §6.3.

## 3. FINDINGS ABOUT OTHER ENGINES (→ upstream_findings.md U8-U10)

### 3.1 U10 — bare script properties read Script, not Script_Extensions, on FOUR scripts (rust, re2, onig, vectorscan)

U2's census found this for `\p{Greek}` on one witness. The first sample
shows it on `\p{Greek}`, `\p{Cyrillic}`, `\p{Latin}` (U+0301 in
`lit-nfc-decomposed-miss`) and `\p{Han}` (U+3001/U+3002 in four throughput
subjects). It is a documented semantics difference (PCRE2 bare script =
scx), not a bug.

### 3.2 U9 — Oniguruma 6.9.10 (UTF-8) folds ß to SS under `(?i)`

`(?i)straße` matches `STRASSE` and `DIE STRASSE`; PCRE2 10.46 folds simply
(one-to-one) and does not. Oniguruma's default case-fold flag includes its
multi-character folds (this reading is from the documented option, not
verified against the source).

### 3.3 U8 — RE2 11.0.0 (UTF-8) matches `\B` between the bytes of one character

On `a é б` (61 C3 A9 D0 B1), RE2 returns `\B` at byte 2 (between C3 and A9).
The oracle's first `\B` is at byte 3. On `a NBSP b` it matches at byte 2
where the oracle has no match at all. Find-all counts rise by 3.0-3.3%
(t-64k 36,728 vs 35,660). The driver's `--utf8` advance only moves the
restart point after an empty match. The first reported position is RE2's
own. Not checked against RE2's issue tracker.

### 6.3 A bench-side cell-time observation (for the manager, not pcrec)

The harness compiles every pattern's whole-subject form (`adapter.compile`
builds both forms regardless of the set's regimes). utf8 declares no
`match` regime, so those artifacts are compiled and reported in the
compile section but never measured. On an auto/nocaps cell they cost 180.6 s
of medians × 5 trials ≈ 15 min. That is ~903 s of the cell, 842 s of it
`prp-l`/`prp-notl`'s whole forms. Whether the compile-axis datum is worth
that is the manager's call. The rows are real compile data, so this is not
a defect. The same wrap puts `(*UCP)` mid-pattern on vectorscan (§5).
