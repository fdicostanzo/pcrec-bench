# ---------------------------------------------------------------------------
# THE FIX (testees/pcre2/driver.c, this file's own header comment has the
# full rule and its man pcre2api citations): call 1 of a find-all runs at
# offset 0 WITHOUT PCRE2_NO_UTF_CHECK (libpcre2 validates the whole
# subject there; an ill-formed one is refused, loudly, by the existing
# `giveup:<code>:<message>` protocol); calls 2..n on the SAME buffer pass
# PCRE2_NO_UTF_CHECK, with every start offset ASSERTED (never trusted) to
# be a character boundary first. `--utf-always-check` is a DRIVER-ONLY
# flag (never in the driver protocol, never passed by adapter.py) that
# restores the pre-fix behaviour -- reachable only by
# `make check-harness`'s control (`check_pcre2_utf_validate_once`,
# tools/selfcheck.py) and by this probe.
#
# pcre2_match() honours PCRE2_NO_UTF_CHECK identically whether or not JIT
# is present (man pcre2api, "Option bits for pcre2_match()": "apart from
# PCRE2_NO_UTF_CHECK when calling pcre2_match()... You might want to do
# this for the second and subsequent calls to pcre2_match() if you are
# making repeated calls to find multiple matches in the same subject
# string" -- and the JIT-supported-options list keeps PCRE2_NO_UTF_CHECK,
# "apart from PCRE2_NO_JIT (obviously)"); this driver never calls a
# separate pcre2_jit_match -- pcre2_match() dispatches to JIT internally
# when compiled (man pcre2jit) -- so ONE call site (`do_match`) and one
# flag cover pcre2-utf-interp and pcre2-utf-jit alike, MEASURED below, not
# merely cited. pcre2_dfa_match() honours the same flag too (man pcre2api,
# "Option bits for pcre2_dfa_match()": "All but the last four of these are
# exactly the same as for pcre2_match()"), also measured below.
#
# ---------------------------------------------------------------------------
