2026-09-01 — bench/altwide ([B11.2]): the ORACLE's own per-pass cost over the
set's own subjects, as the sizing input for NOTES.md's cell-time estimate.

WHAT THIS IS. One pass per (pattern, regime) through `pcrecbench.oracle_pcre2`
— libpcre2 10.46, the INTERPRETER, no JIT — over `bench/altwide`'s 38 short
subjects and 4 throughput subjects, at the pattern set committed in
bench/altwide@0.1. `match` is anchored+end-anchored at offset 0, `search_short`
is unanchored at offset 0, `throughput` is find-all; the same three semantics
`pcrecbench/expectations.py` derives the expectations under.

WHAT THIS IS NOT. A measurement. It ran on a box carrying another session's
battery (load average 6.7-8.0 on 12 cores, `uptime` before and after), with no
quiet gate, no repetition and no spread, and it is one pass rather than a
median of five. It is an UPPER BOUND on an interpreter's per-pass cost, used
to size a cell and to choose the throughput subjects' byte counts. Nothing
here is a number to compare an engine against; the store is where those live.

WHY IT WAS RUN. The set's throughput subjects were 1 MB in the first design
(plan row [B11.2]'s "1 MB-class prose"). The question the probe answers is
whether a backtracking testee's throughput trial would sit on the harness's
20 s per-trial cap at that size — the arithmetic said yes and this says by how
much, which is how the subjects came to be 128 KB and 512 KB
(bench/altwide/NOTES.md, "Cell-time estimate, and what was cut").

--- the script, verbatim ---
"""Design-time timing probe: how long ONE pass costs the ORACLE (libpcre2,
interpreter, no JIT) per pattern per regime, over this set's own subjects.
Not a measurement in the pinned sense -- a sizing input for the cell-time
estimate, run on a box whose load is not controlled."""
import sys, time
sys.path.insert(0,'/home/duxevents/pcrec-bench/worktrees/b112alt')
from pcrecbench.subbench import load
from pcrecbench import oracle_pcre2 as oracle
sb = load('/home/duxevents/pcrec-bench/worktrees/b112alt/bench/altwide')
short = sb.subjects_for('search_short')
tput  = sb.subjects_for('throughput')
sb_bytes = {s.subject_id: sb.subject_bytes(s.subject_id) for s in short+tput}
print("%-10s %10s %10s %10s %10s" % ("pattern","compile_s","match_s","search_s","tput_s"))
tot = {"c":0.0,"m":0.0,"s":0.0,"t":0.0}
for p in sb.patterns:
    txt = sb.pattern_bytes(p.name)
    t0=time.perf_counter(); rx=oracle.compile(txt); c=time.perf_counter()-t0
    t0=time.perf_counter()
    for s in short: rx.match(sb_bytes[s.subject_id],0)
    m=time.perf_counter()-t0
    t0=time.perf_counter()
    for s in short: rx.search(sb_bytes[s.subject_id],0)
    se=time.perf_counter()-t0
    t0=time.perf_counter()
    for s in tput: rx.find_all(sb_bytes[s.subject_id])
    tp=time.perf_counter()-t0
    print("%-10s %10.4f %10.4f %10.4f %10.4f"%(p.name,c,m,se,tp))
    tot["c"]+=c; tot["m"]+=m; tot["s"]+=se; tot["t"]+=tp
print("%-10s %10.4f %10.4f %10.4f %10.4f"%("TOTAL",tot["c"],tot["m"],tot["s"],tot["t"]))
