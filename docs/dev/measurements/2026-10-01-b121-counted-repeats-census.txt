# READING.
#
# ONE hit, `bench/utf8`'s `qnt-counted-3b`: `(?:\xe6\x97\xa5\xe6\x9c\xac){2,}`
# -- the UTF-8 bytes of "日本" (two 3-byte characters) wrapped in a
# counted repeat with no upper bound. Each byte is a separate literal
# atom to this byte-level parser, so the 6-byte run classifies as
# MULTI-LITERAL (>=2 flat literal atoms, no escapes/classes/subgroups)
# -- exactly the `(?:ab){m,n}` shape I-125 describes, just over
# multi-byte text rather than ASCII.
#
# bench/bounded's `nest2-*`/`nest3-*` family -- the one I-125 itself
# names as "the candidate instrument" for the [OPT-5] period-k
# trigger -- does NOT match either shape, confirmed structurally
# rather than assumed: every nest pattern is `(?:CLASS{p,q}){m,n}`
# (e.g. `(?:\d{1,4}){1,4}`, `(?:[a-z]{1,6}){1,6}`, the 3-level
# `(?:(?:\d{1,16}){1,16}){1,16}`) -- a counted repeat of a BOUNDED
# CLASS that itself carries its own inner counted repeat, not a flat
# multi-character literal and not an all-singleton alternation. Its
# OWN body is one Literal escape atom (`\d`) immediately followed by
# `{p,q}` INSIDE the group -- `classify_group_body` correctly reads
# this as neither shape (a single escape atom fails the >=2-atoms
# MULTI-LITERAL test, and there is no alternation to read as
# ALL-SINGLETON). So the nest family, despite being the row's named
# candidate, is a DIFFERENT mechanism shape from what A2/Q7 is asking
# about -- it is `(?:class){m,n}{p,q}` (one class, two nested counted
# repeats), not `(?:ab){m,n}` (one literal STRING, one counted
# repeat). Whether pcrec's [OPT-5] period-k mechanism is meant to
# trigger on the nest family's own shape or specifically on a literal-
# string repeat is a question for pcrec, not settled by this census
# (an ask, not answered here).
#
# No OTHER pattern in the 339-pattern corpus (all 7 sub-benches)
# matches either shape. A2's own decision rule ("any cell in (1)
# where pcrec-auto is behind by more than its IQR meets the D77
# trigger; none means the row stays a candidate with no cell") now
# has exactly ONE candidate cell to time -- `qnt-counted-3b`, NOT a
# nest-family pattern -- queued into the A5 window plan (see
