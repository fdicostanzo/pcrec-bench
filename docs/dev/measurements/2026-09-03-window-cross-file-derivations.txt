# The 30-minute figure is pcre2-JIT's 0.1 cell, not pcrec-auto's. 0.2's

# WHAT 0.1's AUTO CELL ACTUALLY SPENT ITS 4.8 MINUTES ON (R5, summed from
# its own compile-cost table): 114.9 s of refusals (26 of them, once per
# form, never per trial) plus 3.5 s per trial of compiles over 14 cells
# (17.5 s at five trials) = about 2.2 min of compile, so roughly half the
# cell. The other half is matching.
#
# THE SAME SUM ON 0.2 (R1), and the asymmetry it makes visible:
#
#   testee        refusals  refusal cost   compiled cells  compile x5   cell wall
#   pcrec-auto      32       113.8 s        34              65.5 s       8.8 min
#   pcrec-nocaps    32       114.9 s        34              66.0 s       9.1 min
#   pcrec-vm        26         0.6 s        40             334.0 s      17.2 min
#   pcrec-vm-in     26         0.6 s        40             334.0 s      17.2 min
#
# A DFA-route refusal costs 190x what a VM-route refusal costs (113.8 s over
# 32 against 0.6 s over 26), because the source cap is checked after the
# table is materialised and the code cap is reached earlier. But at 0.2's
# widths that no longer makes auto the expensive cell: the VM's SUCCESSFUL
# compiles cost 5x auto's, and the vm cell is twice the auto cell. That
# inverts 0.1's picture, where the ledger recorded auto as the slow arm.
