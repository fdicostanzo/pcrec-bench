# [B31] (the config half), inbox I-32 (vii): THE SIZE CENSUS the raised-cap
# testee axis' bound is derived from, and the evidence a default-cap ruling
# on pcrec's side would need. Every bench/altwide@0.1 pattern x both forms
# x both pcrec engine modes, compiled TWICE -- once at the pin's DEFAULT
# caps (the 0.1 refusal, verbatim) and once under a probe RAISE far above
# anything the set could need -- with pcrec's own emitted-size numbers
# recorded either way. No timing regime, no measurement window: these are
# compile-only wall clocks on a shared box, kept because the COST of a
# refusal is itself one of the findings.
#
# Source: python3 census.py (the script is reproduced at the foot of this
# file), run 2026-09-02 14:59-15:05 EDT on budu-ryzen1600 (12 cores) in
# worktree b31cap, SERIALLY, one pcrec at a time, each exec under
# `/usr/bin/gnutimeout 600`. Box load average at start 1.24, at end 6.43
# (two other lanes of this session were active; every number here is a
# single-threaded compile, and none of them is a benchmark).
#
#   pcrec pin  1989c62 (abi 15), built by testees/pcrec/pin.sh into
#              /home/duxevents/pcrec-bench/build/pcrec-1989c62/build/pcrec
#   defaults   PCREC_MAX_EMIT_BYTES 1,000,000 / PCREC_MAX_VM_EMIT_CODE_BYTES
#              500,000 (testees/pcrec/list_limits.tsv, the pin's own
#              --list-limits)
#   probe      --max-emit-bytes=100000000 --max-emit-code-bytes=100000000
#   base argv  pcrec -p rx --features all [--engine=vm] -o <dir>/artifact.c
#              -- '<pattern>'
#   forms      `plain` is the .rx text; `whole-subject` is
#              `(?:<text>)\z` (pcrecbench/record.py's whole_subject_text)
#   patterns   bench/altwide/patterns/*.rx at worktree b31cap, branch
#              lane/b31cap off master 742c6bc (sha256 of the pattern
#              directory listed at the foot)
#
# THE FOUR FINDINGS
#
#  1. 80 of 80 raised compiles SUCCEEDED. Nothing timed out, nothing hit
#     another limit behind the caps, and the probe raise did not saturate:
#     the largest artifact in the set is 3.7 MB against a 100 MB probe.
#
#  2. THE LARGEST ARTIFACT ON EITHER CAP'S QUANTITY is `s-4096`'s
#     whole-subject FORCED-VM form, 3,741,164 bytes. A forced-VM artifact
#     carries no table initializers, so its TOTAL and its CODE bytes are
#     the same number and one maximum settles both caps. Per mode:
#
#         mode  max emit_bytes            max emit_code_bytes
#         auto  2,586,958  (w-2048 \z)       37,621  (s-4096 \z)
#         vm    3,741,164  (s-4096 \z)    3,741,164  (s-4096 \z)
#
#     The auto route's own code maximum (37,621 B) is an order of magnitude
#     BELOW pcrec's 500,000 default, so a per-mode code bound would have
#     been an illegal LOWERING -- which is why both bigcap configs carry
#     the same pair. THE BOUND: the smallest power of two at or above twice
#     the largest observed value, 2 x 3,741,164 = 7,482,328 -> 8,388,608
#     (8 MiB), for both caps on both configs.
#
#  3. AT THE DEFAULT CAPS, 50 OF THE 80 COMPILES REFUSE -- 26 auto rows at
#     the TOTAL cap and 24 vm rows at the CODE cap. 14 of 20 patterns lose
#     at least one auto form and 12 of 20 at least one vm form. SIX
#     patterns compile on all four (form x mode) cells at the default
#     caps: `floor`, `w-8`, `w-64`, `sh1-64`, `sfx-64`, `nar4-64`. Two
#     more lose exactly one cell -- `w-256` and `cnt-64` both keep three
#     and lose the AUTO WHOLE-SUBJECT form, the `\z` anchoring being what
#     pushes each over the total cap. The other twelve lose at least two.
#
#  4. A REFUSAL IS NOT FREE, AND THE TWO ROUTES DIFFER BY THREE ORDERS OF
#     MAGNITUDE. Both caps are checked AFTER emission, so the emitter runs
#     to completion and is then thrown away: an auto-route refusal costs
#     0.07-40.23 s (the DFA subset construction dominates and grows with
#     width), a forced-VM refusal 0.01-0.07 s. The most expensive single
#     refusal in the set is `s-4096` whole-subject under auto at 40.23 s;
#     the whole 20-pattern set costs about 116 s of auto-route refusals per
#     form pair. `raised_s` and `default_s` below are the SAME compile
#     either side of the cap check, and they agree to within the noise of a
#     shared box -- which is the direct evidence for "checked after
#     emission".
#
# COLUMNS. `emit_bytes` / `emit_code_bytes` are pcrec's own two size
# quantities (comment-excluded C source summed over the emitted .c and .h;
# total, and total minus table initializers), computed by
# testees/pcrec/adapter.py's `emit_size` port. On all 61 rows where pcrec's
# own advisory `--warn-emit-bytes` line fired (the default 250,000
# threshold), THE PORT AGREED WITH PCREC BYTE-EXACTLY on both numbers; the
# 19 rows below the threshold have no independent witness and carry the
# port's numbers alone. `raw_bytes` is the .c + .h on disk, comments and
# all. `default_cap` is which cap refused (`total` = --max-emit-bytes,
# `code` = --max-emit-code-bytes) and `default_bytes` is the size PCREC
# QUOTED in its own refusal, which is the same quantity as `emit_bytes` /
# `emit_code_bytes` respectively and differs by the handful of bytes the
# raise flags add to the emitted provenance comment.
