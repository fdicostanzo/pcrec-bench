# ---- FOLLOW-UP WITNESSES (probe_tre_bracket_escape_followups.c) -------
(1) csv5 [^,\n] crosses an embedded newline it should exclude:
  csv5 vs "a,b,c,d,e\nZZZZZZZZZZ"              MATCH [0,20) = "a,b,c,d,e
ZZZZZZZZZZ"
  (oracle/PCRE reading would stop the class at the newline;
   the whole line above is one 20-byte match under TRE)

(2) [^"\\] / doubled-backslash idiom: coincidentally SAFE:
  [^"\\]+ vs "\\" (a lone backslash byte)      nomatch
  [^"\\]+ vs "quoted\"here"                    MATCH [0,6) = "quoted"
  (both a literal backslash byte AND a literal '"' byte are
   correctly EXCLUDED -- the doubled escape happens to mean
   the same thing whether or not backslash is special)

(3) tag-pair-match [\w:-] accepts accidental members, not \w:
  [\w:-]+ vs "w" (should be a real \w match anyway) MATCH [0,1) = "w"
  [\w:-]+ vs "5" (a digit -- \w should match, TRE's literal set does not) nomatch
  [\w:-]+ vs "\\" (a lone backslash -- \w should NOT match, TRE's literal set DOES) MATCH [0,1) = "\"
